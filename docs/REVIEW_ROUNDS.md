# Review rounds

Six adversarial critique rounds, each from a different reviewer persona, run against the code as
committed. Every round lists what was checked, the findings with severity (H = could mislead a
user or produce a wrong result, M = real defect or gap with limited reach, L = polish), what was
fixed (with the regression test in `tests/test_review_regressions.py` where one applies), and
what was deliberately not fixed and why.

Standing constraint during these rounds: the stress experiments under `results/stress_*.json`
were being generated by a background job from the code as it stood. Nothing that changes a
stress, planner, verifier or disturbance *number* was altered, because that would make stored
results disagree with the code. Fixes in those modules are output-neutral (checked by tests) and
anything numerically significant is listed as "not fixed" for the owner.

## Round 1: EDGE-style engineer (practicality, scale, determinism, spec/format usability)

Checked: the show validator against 16 malformed inputs; memory and time scaling of the
planner/assignment helpers; whether the Monte-Carlo runner works on the owner's platform
(Windows); determinism of artefacts that CI diffs; encoding of every file read/write; whether
the tool can be used without writing Python.

Findings
- H1. `validate_show` crashed (KeyError / TypeError / AttributeError) on 7 of 16 malformed
  inputs (geofence without `x`, crowd without `y`, string `hold_s` or `z_max`, a stage that is
  not an object, ...). A validator is the front door for hand-written spec files; it must
  return errors, not tracebacks. It also accepted `inf` limits and a declared separation
  threshold *below one vehicle diameter* (e.g. 0.3 m for a 0.48 m vehicle), which would let a
  "PASS" certificate describe aircraft that physically overlap.
- M2. `monte_carlo(workers>1)` hard-coded `multiprocessing.get_context("fork")`, which does not
  exist on Windows (the owner's development platform): `ValueError` the moment a user passes
  `workers=2`.
- M3. `linear_conflicts` (called by every planner for every transition) built several dense
  n x n x 3 arrays: about 100 MB per array at n = 2000 and roughly 1 GB per array at n = 6500, a
  scale the research notes cite for real UAE shows. Memory, not time, was the cliff.
- M4. No command-line entry point: planning, verifying and re-checking an export required
  writing Python.
- M5. CI "determinism" check diffed `viewer/data/index.json` at full float precision. Values in
  it come from LAPACK eigenvalues and floating-point Monte-Carlo, which can differ in the last
  bits between CPUs/BLAS builds, so the check would fail spuriously on a different runner while
  still passing here.
- L6. Text files were read and written with the platform default encoding (cp1252 on Windows).
  Currently harmless because the JSON is ASCII-escaped, but fragile.
- L7. `docs/ARCHITECTURE.md` promised `schema/show.schema.json`, which does not exist.

Fixed
- H1: `validate_show` rewritten to type-check every field it touches and never raise; rejects
  non-finite and non-positive limits, malformed geofence/crowd, non-object stages/vehicle, and
  `min_separation_m < 2 * vehicle.radius_m`. 14 parametrised regression tests.
- M2: `_fork_available()`; without fork the runner falls back to serial execution (identical
  numbers, since each trial has its own seed). Test monkeypatches the platform.
- M3: `linear_conflicts` processes row blocks (peak 124 MB at n = 4000 instead of several GB);
  test compares against a double-loop reference for several block sizes.
- M4: `python -m sirb {validate,plan,check}` (also `sirb` console script). Exit codes: 0 ok,
  1 invalid input or tampered/stale export, 2 verified but FAILED a limit. Output always says
  "simulation-validated only; not an approval". Test covers the tamper case.
- M5: `scripts/build_viewer_data.py` rounds floats to 6 decimals in `index.json`; the committed
  file was rewritten with the same function (no new numbers; hashes and verdicts unchanged).
- L6: explicit `encoding="utf-8"` in `load_show` / `save_show`. L7: doc corrected.

Not fixed (and why)
- `assign_hungarian_*` and `assign_greedy` still build an n x n cost matrix (8 n^2 bytes:
  about 340 MB at n = 6500) and Hungarian is O(n^3) in the worst case. Not measured above
  n = 2000 (the scaling experiment). A sparse or k-nearest-candidate assignment is a design
  change, listed for NEXT_STEPS.
- Scripts and Makefile assume the repository root as working directory and a POSIX `make`.
  Documented in `docs/SHOW_SCHEMA.md`; PowerShell users run the `python scripts/...` lines
  directly.
- No machine-readable JSON Schema file. Adding one without a validator dependency would create
  a second source of truth that can drift; the validator is the specification.

## Round 2: TII-style robotics researcher (mathematical correctness, unstated assumptions, statistics)

Checked: the verifier's exactness claim by attack (400 random degree 1..7 polynomial pairs,
segment lengths 1 to 600 s, forced near-grazing, truth from a 400,001-point grid plus bounded
local minimisation: worst verifier-minus-truth gap 3e-14 m, 0 cases above 1e-7); the closed-form
planner constants (peak speed 1.875, peak acceleration 5.7735, peak jerk 60 for the quintic);
the Lipschitz margin used by the prioritized planner; the continuity checks across breakpoints;
the stress model's equations, discretisation, wind delay indexing, Gauss-Markov and dead-reckoning
variances; the candidate-pair pruning against all pairs; seed handling and what the Wilson
intervals do and do not cover.

Findings
- H1. Continuity checks stopped one derivative too early. Position and velocity jumps were
  flagged, but an *acceleration* step between segments (infinite jerk) passed, so a path with
  a step in commanded acceleration could receive PASS and a certificate sentence saying jerk
  limits hold. (Demonstrated with x = 0.5 t^2 followed by x = 0.5 + t.)
- H2. The GNSS-dropout `hold` / `rejoin` contingency blends the reference back to the moving
  nominal path over a fixed 6 s with no speed limit. On `sirb_text_100` with 30% of drones in
  dropout the reference reached 23.4 m/s against a 10 m/s horizontal limit (46 m/s in a
  synthetic stop-and-go case), and the tracking loop follows it. Rejoin rows in the contingency
  experiment are therefore optimistic.
- M3. Unstated model assumptions that change how stress numbers read: perfect acceleration
  feed-forward (the error equation does not depend on the reference); no actuator or airframe
  wind limit while the wind sweep goes to W20 = 20 m/s (mean wind of about 27.7 m/s at 60 m,
  three times the X7 published 9 m/s sustained limit); GNSS white noise drawn once per step so
  its effect depends on dt; independent per-drone GNSS error (conservative for RTK, not for a
  shared spoofing pull-off); "Dryden" turbulence is intensity-only with a fixed correlation time.
- M4. Seed structure undocumented. Sweeps reuse the same random streams in row 0 of every
  sweep; spacing rows use common random numbers; Wilson intervals are per row, not
  simultaneous; scaling rows have 6 to 20 trials and their `p_violation` is not an estimate.
- L5. `dev_bound`, the pad that decides which pairs are ever examined, is a heuristic. Empirically
  safe (0 of 2,953 violating pairs missed across five stressed configurations) but unproven.

Fixed
- H1: `accel_discontinuity` structural check (tolerance 1e-3 m/s^2, mirrored in the certificate
  method text, guarantees text, Arabic guarantee string, methods page and `docs/VERIFIER.md`).
  Planner output is unaffected (rest-to-rest quintics have zero acceleration at both ends); the
  committed viewer certificates were regenerated and differ only in text and the new tolerance
  entry. Tests: step flagged, smooth chain accepted, planner output clean.
- H2 (partly): `StressConfig.rejoin_vmax` (default `None` = stored behaviour) lengthens the
  blend to cap its closing speed. Test: default peaks above 25 m/s on a 100 m gap, capped run
  stays within 10.1 m/s and still rejoins.
- M3/M4/L5: documented in `docs/METHODS.md` section 5 with the computed numbers; a regression
  test now compares pruned and all-pairs violating sets on stressed runs (and asserts that the
  test actually contains violations).

Not fixed (and why)
- The rejoin cap is opt-in, not default, and `make stress` does not use it. Making it default
  changes contingency numbers while the experiment job is producing them, so the shipped
  contingency rows keep the caveat. Owner decision: rerun contingency with `rejoin_vmax = 10`
  (the horizontal limit) before quoting any `hold`/`rejoin` row.
- No saturation/wind-limit in the tracking model, no feed-forward error and no
  common-mode GNSS option. Each is a model change that alters every stress number. Listed for
  NEXT_STEPS.
- `Fleet.content_hash` hashes raw bytes without length prefixes, so two different fleets could
  in principle serialise to the same byte stream. Constructing such a pair needs coefficient
  bytes that reproduce a segment header; not exploitable by accident, and changing the hash
  invalidates every stored hash. A length-prefixed encoding is a v2 item.
