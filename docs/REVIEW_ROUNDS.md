# Review rounds

Six adversarial critique rounds, each from a different reviewer persona, run against the code as
committed. Every round lists what was checked, the findings with severity (H = could mislead a
user or produce a wrong result, M = real defect or gap with limited reach, L = polish), what was
fixed (with the regression test in `tests/test_review_regressions.py` where one applies), and
what was deliberately not fixed and why.

Standing constraint during these rounds: the stress experiments under `results/stress_*.json`
were being generated by a background job from the code as it stood. Nothing that changes a
stress, planner, verifier or disturbance *number* was altered, because that would make stored
results disagree with the code. Fixes in those modules are output-neutral (checked by tests) and
anything numerically significant is listed as "not fixed" for the owner.

## Round 1: EDGE-style engineer (practicality, scale, determinism, spec/format usability)

Checked: the show validator against 16 malformed inputs; memory and time scaling of the
planner/assignment helpers; whether the Monte-Carlo runner works on the owner's platform
(Windows); determinism of artefacts that CI diffs; encoding of every file read/write; whether
the tool can be used without writing Python.

Findings
- H1. `validate_show` crashed (KeyError / TypeError / AttributeError) on 7 of 16 malformed
  inputs (geofence without `x`, crowd without `y`, string `hold_s` or `z_max`, a stage that is
  not an object, ...). A validator is the front door for hand-written spec files; it must
  return errors, not tracebacks. It also accepted `inf` limits and a declared separation
  threshold *below one vehicle diameter* (e.g. 0.3 m for a 0.48 m vehicle), which would let a
  "PASS" certificate describe aircraft that physically overlap.
- M2. `monte_carlo(workers>1)` hard-coded `multiprocessing.get_context("fork")`, which does not
  exist on Windows (the owner's development platform): `ValueError` the moment a user passes
  `workers=2`.
- M3. `linear_conflicts` (called by every planner for every transition) built several dense
  n x n x 3 arrays: about 100 MB per array at n = 2000 and roughly 1 GB per array at n = 6500, a
  scale the research notes cite for real UAE shows. Memory, not time, was the cliff.
- M4. No command-line entry point: planning, verifying and re-checking an export required
  writing Python.
- M5. CI "determinism" check diffed `viewer/data/index.json` at full float precision. Values in
  it come from LAPACK eigenvalues and floating-point Monte-Carlo, which can differ in the last
  bits between CPUs/BLAS builds, so the check would fail spuriously on a different runner while
  still passing here.
- L6. Text files were read and written with the platform default encoding (cp1252 on Windows).
  Currently harmless because the JSON is ASCII-escaped, but fragile.
- L7. `docs/ARCHITECTURE.md` promised `schema/show.schema.json`, which does not exist.

Fixed
- H1: `validate_show` rewritten to type-check every field it touches and never raise; rejects
  non-finite and non-positive limits, malformed geofence/crowd, non-object stages/vehicle, and
  `min_separation_m < 2 * vehicle.radius_m`. 14 parametrised regression tests.
- M2: `_fork_available()`; without fork the runner falls back to serial execution (identical
  numbers, since each trial has its own seed). Test monkeypatches the platform.
- M3: `linear_conflicts` processes row blocks (peak 124 MB at n = 4000 instead of several GB);
  test compares against a double-loop reference for several block sizes.
- M4: `python -m sirb {validate,plan,check}` (also `sirb` console script). Exit codes: 0 ok,
  1 invalid input or tampered/stale export, 2 verified but FAILED a limit. Output always says
  "simulation-validated only; not an approval". Test covers the tamper case.
- M5: `scripts/build_viewer_data.py` rounds floats to 6 decimals in `index.json`; the committed
  file was rewritten with the same function (no new numbers; hashes and verdicts unchanged).
- L6: explicit `encoding="utf-8"` in `load_show` / `save_show`. L7: doc corrected.

Not fixed (and why)
- `assign_hungarian_*` and `assign_greedy` still build an n x n cost matrix (8 n^2 bytes:
  about 340 MB at n = 6500) and Hungarian is O(n^3) in the worst case. Not measured above
  n = 2000 (the scaling experiment). A sparse or k-nearest-candidate assignment is a design
  change, listed for NEXT_STEPS.
- Scripts and Makefile assume the repository root as working directory and a POSIX `make`.
  Documented in `docs/SHOW_SCHEMA.md`; PowerShell users run the `python scripts/...` lines
  directly.
- No machine-readable JSON Schema file. Adding one without a validator dependency would create
  a second source of truth that can drift; the validator is the specification.

## Round 2: TII-style robotics researcher (mathematical correctness, unstated assumptions, statistics)

Checked: the verifier's exactness claim by attack (400 random degree 1..7 polynomial pairs,
segment lengths 1 to 600 s, forced near-grazing, truth from a 400,001-point grid plus bounded
local minimisation: worst verifier-minus-truth gap 3e-14 m, 0 cases above 1e-7); the closed-form
planner constants (peak speed 1.875, peak acceleration 5.7735, peak jerk 60 for the quintic);
the Lipschitz margin used by the prioritized planner; the continuity checks across breakpoints;
the stress model's equations, discretisation, wind delay indexing, Gauss-Markov and dead-reckoning
variances; the candidate-pair pruning against all pairs; seed handling and what the Wilson
intervals do and do not cover.

Findings
- H1. Continuity checks stopped one derivative too early. Position and velocity jumps were
  flagged, but an *acceleration* step between segments (infinite jerk) passed, so a path with
  a step in commanded acceleration could receive PASS and a certificate sentence saying jerk
  limits hold. (Demonstrated with x = 0.5 t^2 followed by x = 0.5 + t.)
- H2. The GNSS-dropout `hold` / `rejoin` contingency blends the reference back to the moving
  nominal path over a fixed 6 s with no speed limit. On `sirb_text_100` with 30% of drones in
  dropout the reference reached 23.4 m/s against a 10 m/s horizontal limit (46 m/s in a
  synthetic stop-and-go case), and the tracking loop follows it. Rejoin rows in the contingency
  experiment are therefore optimistic.
- M3. Unstated model assumptions that change how stress numbers read: perfect acceleration
  feed-forward (the error equation does not depend on the reference); no actuator or airframe
  wind limit while the wind sweep goes to W20 = 20 m/s (mean wind of about 27.7 m/s at 60 m,
  three times the X7 published 9 m/s sustained limit); GNSS white noise drawn once per step so
  its effect depends on dt; independent per-drone GNSS error (conservative for RTK, not for a
  shared spoofing pull-off); "Dryden" turbulence is intensity-only with a fixed correlation time.
- M4. Seed structure undocumented. Sweeps reuse the same random streams in row 0 of every
  sweep; spacing rows use common random numbers; Wilson intervals are per row, not
  simultaneous; scaling rows have 6 to 20 trials and their `p_violation` is not an estimate.
- L5. `dev_bound`, the pad that decides which pairs are ever examined, is a heuristic. Empirically
  safe (0 of 2,953 violating pairs missed across five stressed configurations) but unproven.

Fixed
- H1: `accel_discontinuity` structural check (tolerance 1e-3 m/s^2, mirrored in the certificate
  method text, guarantees text, Arabic guarantee string, methods page and `docs/VERIFIER.md`).
  Planner output is unaffected (rest-to-rest quintics have zero acceleration at both ends); the
  committed viewer certificates were regenerated and differ only in text and the new tolerance
  entry. Tests: step flagged, smooth chain accepted, planner output clean.
- H2 (partly): `StressConfig.rejoin_vmax` (default `None` = stored behaviour) lengthens the
  blend to cap its closing speed. Test: default peaks above 25 m/s on a 100 m gap, capped run
  stays within 10.1 m/s and still rejoins.
- M3/M4/L5: documented in `docs/METHODS.md` section 5 with the computed numbers; a regression
  test now compares pruned and all-pairs violating sets on stressed runs (and asserts that the
  test actually contains violations).

Not fixed (and why)
- The rejoin cap is opt-in, not default, and `make stress` does not use it. Making it default
  changes contingency numbers while the experiment job is producing them, so the shipped
  contingency rows keep the caveat. Owner decision: rerun contingency with `rejoin_vmax = 10`
  (the horizontal limit) before quoting any `hold`/`rejoin` row.
- No saturation/wind-limit in the tracking model, no feed-forward error and no
  common-mode GNSS option. Each is a model change that alters every stress number. Listed for
  NEXT_STEPS.
- `Fleet.content_hash` hashes raw bytes without length prefixes, so two different fleets could
  in principle serialise to the same byte stream. Constructing such a pair needs coefficient
  bytes that reproduce a segment header; not exploitable by accident, and changing the hash
  invalidates every stored hash. A length-prefixed encoding is a v2 item.

## Round 3: Al Ain University senior (clarity, reproducibility, docs-code consistency, claims versus evidence)

Checked: every statement in README, plan, ARCHITECTURE, METHODS, VERIFIER, VIEWER, SHOW_SCHEMA and
DATA_SOURCES against the code or `results/*.json`; what a reader following the README would
actually be able to run; whether "reproducible" survives timing fields and Windows.

Findings
- H1. METHODS section 8 said the 2.0 m separation threshold follows "cited published guidance".
  It does not: RESEARCH.md cites a 50 m crowd buffer (CAP 722E, AC-010) and no source for 2.0 m,
  and `sirb/spec.py` itself labels it ASSUMPTION. The sentence gave an assumed number borrowed
  authority.
- H2. METHODS section 3 said the stronger planners "help only on crossing assignments" and "fail
  on 200+ drone pinned cases". `results/planners.json` shows both fail on *all four* shows
  including the 100-drone one, and shows no case in which either rescues a failing baseline. The
  benchmark gives no evidence that they add capability, and the text claimed otherwise.
- H3. README was the Phase 1 text: "Nothing below the research layer is implemented", a
  "(planned)" method list, no commands. It also called the output a "collision-free" plan and
  an "independently verified" certificate, which can be read as third-party validation.
- M4. ARCHITECTURE described things that do not exist or work differently: geofence polygons,
  step/ramp GNSS spoofing, battery capacity variance, a `docs/REPORT.md` with a consistency test,
  "separation measured with the same exact method as the verifier" (the stress code uses an
  exact minimum over piecewise-linear interpolation and never imports the verifier), a
  bounding-sphere prefilter (boxes are built), a browser smoke test and a "reproduction check" in CI
  (CI only diffs `index.json`), a `required nominal separation` function (none existed), a
  `waves.py` planner missing from the table.
- M5. plan.md's "500+ drones smooth" was never measured; nothing in the repo supports it.
- M6. "Reproducible" is true for numbers, false for the `*_runtime_s`, `wall_s` and `*_cpu_s`
  fields stored next to them; this was not said anywhere, nor that last-bit float differences are
  possible across BLAS builds.
- L7. The contingency table calls the GNSS-dropout behaviour `hold`, but the code runs the
  rejoin blend for it; METHODS did not say so (now covered in the round 2 note on rejoin).
- L8. RESEARCH.md promised Dryden scale lengths; the code uses intensities and a fixed
  correlation time.

Fixed
- H1, H2, M4, L8: corrected in METHODS, ARCHITECTURE, RESEARCH; new tests assert the 2.0 m
  provenance sentence and the spec label, and that METHODS quotes the current stress defaults.
- H3: README rewritten: real status, a "What the evidence supports" section (independent in
  code and method, not in authorship; planner benchmark outcome; stress numbers are model
  properties; limited-search novelty claim), working commands, Windows note, what is and is not
  deterministic, layout, limitations. The word "collision-free" no longer appears as a promise.
- M5, M6: plan.md status section; README reproducibility paragraph.
- M4 (missing function): `sirb.stress.required_value(rows, target)` implements the plan's
  "separation required for a stated risk target" conservatively (a value qualifies only if its
  Wilson upper bound and that of every larger tabulated value meet the target; targets below the
  attainable bound return `None`). Tested.
- New tests: worker-count independence of Monte-Carlo output, docs list every shape type and
  letter the code supports.

Not fixed (and why)
- No `docs/REPORT.md` or consistency test between a report and results: the report belongs to
  the Final milestone and the stress results are still being generated.
- Milestone tags v0.5.0 / v0.6.0 / v0.6.1 not created: they should mark finished experiments.
- No frame-rate measurement for the viewer: needs a real GPU/browser; listed as unmet in plan.md.

## Round 4: aviation safety assessor (overclaiming, wording of guarantees, missing failure modes, misreadable output)

Checked: every user-facing string (viewer EN and AR strings, `index.html`, `methods.html`,
`app.js` templates, CLI output, certificate text, export labels, README) for words that could be
read as approval, clearance or independent validation; the UAE-rule statements against what
RESEARCH.md marks UNVERIFIED; which failure modes the stress metric and the docs cover; what
`PASS` actually means when inputs are incomplete.

Findings
- H1. The viewer labelled a same-code re-run "Independent recheck" (`independent_recheck` in
  the data, an `#independent-recheck` anchor), while its own methods page said "a recomputation
  by the same verifier code". The label contradicted the explanation and claimed independence
  that does not exist.
- H2. A certificate returned `PASS` and listed "Dynamic limits (speed, ... geofence, crowd) hold"
  even when those limits were missing from the limits dict: `verify()` silently skips absent
  limits (only `min_separation_m` is required). A caller could receive a green PASS for
  checks that never ran.
- H3. "Certificate" and a green tick beside "PASS" read as an official certification. The
  panel title, the tick glyph, the page `<title>`-level description ("verified drone-show plans"),
  the canvas label ("verified drone formation") and the CLI line `verdict: PASS` all lacked the
  qualifier "against the limits declared in the show file, several of which are assumptions".
- M4. Missing failure modes were undocumented or only implied: the stress metric measures
  inter-drone distance only (no geofence, crowd distance or ground impact under disturbance; the
  corridor behaviour can leave the geofence); no fleet-level abort or termination logic; the
  demo plans pass with margins of 0.19 to 0.45 m over an assumed threshold while the wind+GNSS
  scenario of the same show goes below it (1.48 m sampled), which a reader of a green PASS
  next to it could miss.
- M5. The legend's "Green: otherwise" invites reading green as safe.
- L6. RESEARCH.md quoted "1,000 drones for a GCAA-hosted ICAO symposium dinner" with no source.
- UAE rules: checked. The only UAE regulatory content is RESEARCH.md section 4, which is
  marked UNVERIFIED (CAR-UAS Issue 01 possibly not current; Dubai and Abu Dhabi primary pages
  and current no-fly maps not verified; no swarm provisions). Everywhere else the text says only
  that approvals are required and the UAE rule set was not verified. The 50 m crowd buffer is
  cited to UK CAP 722E and Hong Kong AC-010, not to UAE rules, and METHODS now says so.

Fixed
- H1: renamed to "Recomputation check (same verifier code, re-run)" in EN and AR, data key
  `recomputation_ok`, anchor `#recomputation-check`; VIEWER.md updated; test fails if the old name
  reappears anywhere in `viewer/`.
- H2: verdict is `PASS` only if nothing failed and every limit family was supplied; otherwise
  `INCOMPLETE` with an `unchecked_limits` list, enforced again by `verify_certificate`.
  Regression test builds exactly the silent-skip case. Committed viewer certificates regenerated
  (they gain `"unchecked_limits": []`, nothing else changes).
- H3, M5: panel is "Verification record (not an approval or regulatory certificate)" with a
  visible note under the verdict ("means only that the paths as written meet the limits declared
  in the show file, several of which are assumptions ..."); no tick on PASS; qualified canvas,
  description and legend strings; CLI prints "against the limits declared in the show file only";
  README and VERIFIER.md define "certificate". A test requires every UI line containing
  safe/approved/cleared/certified to negate it, and EN/AR key parity.
- M4: scope sentence in the scenario panel (EN and AR) and METHODS section 9 items 9 to 11.
- L6: flagged UNVERIFIED in RESEARCH.md.

Not fixed (and why)
- The code still says `certificate` (module, file name, JSON key). Renaming is an API break across
  scripts, tests and stored data; the term is defined wherever it is shown to a reader.
- No fleet-level abort logic, geofence/crowd checks under disturbance, launch/landing stage or
  ground-impact model. These are new models, not wording fixes; listed as limits.
- `PreflightReport.ok` is true when no FAIL finding exists. The report always carries a
  `NOT_CHECKED` INFO finding naming what was not checked; renaming `ok` would break callers.

## Round 5: ATRC-style engineer (architecture, API boundaries, verifier independence, test quality)

Checked: the import graph mechanically (AST of every module in `sirb/`, including function-level
and relative imports, followed transitively); where state crosses module boundaries; whether
public functions fail closed on bad input; test oracles (what each test would catch), including
a mutation check on the verifier tests; adversarial inputs to the verifier (coefficients of
1e160 and 1e170, 1e-12 s segments, 1e9 s segments, a drone starting at 1e7 s, coincident
stationary drones: no crash, every genuine violation reported).

Findings
- H1. `preflight` did not fail closed. A NaN in the loaded centre, loaded heading or wind
  forecast made every comparison False, so it reported `ok = True` with no finding (reproduced
  against the previous code: NaN centre gave `ok = True`); a missing key raised KeyError.
- H2. `load_export` recomputed the certificate from the *certificate's own copy* of the limits and
  never compared it with `show.limits`. Editing the show's limits (looser or stricter) beside an
  untouched certificate was accepted, and a consumer reading `show.limits` would trust a PASS
  computed against other limits. The embedded show was not validated, and structurally wrong
  bundles raised TypeError/AttributeError (a traceback from the CLI) rather than ValueError.
- M3. Verifier independence was a claim in three documents, not a check. Mechanical result:
  `sirb/verify.py` imports nothing from `sirb`, not even `trajectory.py`; no planner, assignment,
  shape, spec, stress, disturbance or contingency module reaches `verify`, `certificate`,
  `export`, `preflight` or `cli`. The statement "shares only the data classes" was slightly off
  in the other direction: the verifier does not import them at all (duck typing), while
  `trajectory.py` is described as "data classes only" yet contains evaluation, sampling,
  hashing and parsing helpers.
- M4. Test power. `test_clean_passes` asserted `a or b or c` where `c` held for any clean fleet.
  `test_noise_free_matches_exact_verifier` compares a minimum attained while drones are at rest,
  so it cannot see interpolation error in motion. `test_risk_increases_with_gnss_differential_error`
  asserts p = 0 and p = 1 from 8 trials each (a smoke test, not a monotonicity test). Nothing
  showed the verifier tests could detect a broken verifier.
- L5. `monte_carlo` left the reference array in a module-level dict after returning (memory
  retained, not re-entrant). Duplicated helpers: `_assign` in three planner modules,
  `drone_plan_hash` duplicating the fleet hash loop; a private `_pieces` argument in the public
  `pair_minima` signature.

Fixed
- H1: `_check_inputs` returns `INPUT_INVALID` FAIL findings for missing, non-numeric, non-finite
  or wrong-length centre/heading and for invalid wind inputs. Test covers 5 malformed cases plus
  the clean case.
- H2: `load_export` now validates the embedded show, requires fleet size = `n_drones`, requires
  `certificate.limits == show.limits` after a JSON round trip, and converts every structural
  failure to ValueError. The docstring and README state that this detects accidental change and
  is not authentication. Test: looser show limits, `fleet = []`, `certificate = None`, missing
  show, wrong `n_drones`, malformed geofence, and a JSON list at top level.
- M3: `tests/test_review_regressions.py` builds the import graph with `ast`, asserts the verifier
  imports nothing, that producers cannot reach the judges, and that the checker itself works by
  planting a forbidden import in a copy of the package. `trajectory.py` docstring corrected.
- M4: tautology replaced by an exact-versus-dense-sampling assertion and a lower-bound assertion;
  mutation test replaces the root finder by the safety grid alone and requires the grazing case to
  be missed by the mutant (error above 1e-3 m) and found by the real code (1e-9).
- L5: `_WORK` is cleared in `finally`; test added.

Not fixed (and why)
- The duplicated helpers and the `_pieces` argument stay. They sit in modules that the running
  experiment job imports (planner, verify, stress); a refactor with no behaviour change has no
  numerical payoff and a nonzero chance of breaking an in-flight experiment. Candidate for
  NEXT_STEPS.
- The noise-free stress-versus-verifier test still checks only a static minimum; a test of the
  interpolation error in motion needs curved reference paths, which the current planners do not
  produce. The documented bound (METHODS section 5) is analytic, not measured.
- Weak statistical smoke tests remain as smoke tests; they are labelled as such here, not
  strengthened by adding trials (CI time).

## Round 6: security, dependency and coverage pass

Checked: installed versions and license metadata of every declared dependency and its
transitive dev dependencies against `docs/DATA_SOURCES.md`; `pip check`; the vendored three.js
files against the npm tarball; XSS surface of the viewer, both statically and by loading a
poisoned copy of the data in headless Chromium; path handling in `load_show` / `load_export`;
secrets in the working tree and the whole git history; CI workflow permissions; line and branch
coverage with `pytest-cov` (installed ad hoc, not a declared dependency).

Findings
- M1. `load_show` / `load_export` read any path with no checks: a device file such as
  `/dev/zero` or a FIFO hangs or exhausts memory, and an arbitrarily large file is read whole.
  (Path traversal is not an issue for a local CLI that is given the path by its user; the
  scripts write only to fixed locations.)
- M2. The verifier documents "polynomial degree up to 7" but enforced nothing: a degree-2000
  coefficient array from an untrusted export is expanded into n x K x K work arrays (about 32 MB
  per piece at K = 2000) and root-found at degree 4000, a denial of service and numerically
  meaningless.
- M3. Documentation gaps in `docs/DATA_SOURCES.md`: transitive dev dependencies were not listed;
  the bundled-library note named OpenBLAS only, while numpy/scipy wheels also bundle libgfortran
  (GPL-3.0 with the GCC Runtime Library Exception) and libquadmath (LGPL), per the bundled LICENSE
  text. Sirb does not redistribute them, but the statement was incomplete. No hash was recorded
  for the vendored three.js files.
- M4. Installs were unpinned ranges, so "deterministic given library versions" had no way to
  state the versions; CI ran with the default (write-capable) token permissions.
- L5. No Content-Security-Policy on the viewer pages.
- Clean results: licenses in metadata agree with DATA_SOURCES (numpy BSD-3-Clause AND 0BSD AND MIT
  AND Zlib AND CC0-1.0; scipy BSD; pytest MIT; hypothesis MPL-2.0, dev only; ruff MIT);
  `pip check` reports no broken requirements; runtime dependencies are numpy and scipy only.
  Vendored `three.module.min.js`, `OrbitControls.js` and `LICENSE` are byte-identical to
  `three@0.170.0` (tarball sha512 matches the registry). The viewer has no HTML injection sinks;
  a copy of the data with `<img onerror>` and `<svg onload>` payloads in every string field
  rendered them as text and ran no script. A scan for key, token and private-key patterns over
  all tracked and untracked files and all history found nothing; no `.env`, key or credential
  files are tracked; no absolute local paths in the repository.
- Coverage (statements and branches, 150 tests before the additions below): 92% total. Lowest:
  `planner/common.py` 74% (two unused helpers, `path_segments`, `path_duration`, are dead
  code), `cli.py` 78%, `spec.py` 83%, `planner/prioritized.py` 85%, `stress.py` 91% (the
  `sweep` driver ran only from scripts). The uncovered part of `prioritized.py` is exactly its
  retry machinery: promotion after a failed drone, window widening and the fine-refinement branch
  never run in any test, because the demo shows never need them. That is also the code that
  failed on every `pinned15` case.

Fixed
- M1: `sirb/fileio.py::read_text_limited` (regular files only, 512 MiB cap, UTF-8) used by
  `load_show` and `load_export`; tests for a directory, `/dev/zero`, a FIFO, an oversize file and
  a missing file.
- M2: `MAX_DEGREE = 7`; trailing all-zero rows are trimmed (a padded line is still a line) and a
  genuinely higher degree is reported as `unsupported_degree` and excluded from geometry. Tests
  cover both, and malformed/unreadable segments (wrong width, 1-D, empty, string time, infinite
  time).
- M3, M4: DATA_SOURCES updated with transitive dependencies, bundled libraries, vendored hashes
  (a test recomputes them); `constraints.txt` with exact versions, used by the Makefile and CI
  (`pip install -c constraints.txt`); CI `permissions: contents: read`.
- L5: CSP meta tag on both pages (hash-allowed inline scripts), verified in headless Chromium
  (page works; an injected inline script is refused); a test keeps the hashes in step with the
  inline scripts. `docs/VIEWER.md` has the security notes.
- Coverage: new tests for `apply_events` dispatch of every behaviour (previously exercised only
  by scripts), each `verify_certificate` rejection branch (11 mutations), CLI error paths,
  `python -m sirb`, `sweep`, malformed verifier inputs. Total after additions is above 92%.
- New standing tests: no secret-shaped strings or credential files in tracked files; no HTML sink
  patterns in the viewer.

Not fixed (and why)
- GitHub Actions are pinned by tag (`actions/checkout@v4`, `actions/setup-python@v5`), not
  commit SHA: the commit SHAs could not be retrieved in this session (GitHub API access was not
  available). Owner should pin them when the repository is public.
- `style-src` still needs `'unsafe-inline'` (one inline `style` attribute in `methods.html`);
  moving it to the stylesheet is a cosmetic change deferred to M9. `frame-ancestors` and other
  header-only protections need host configuration.
- Dead helpers in `planner/common.py` and the untested retry machinery of the prioritized
  planner stay: that module is imported by the experiment job, and a test for the retry path
  needs a purpose-built crossing case that the current planner may not solve (see round 3).
- `pytest-cov` is not added to the dev extras; coverage is an occasional check, not a gate.
- Integrity of exports and certificates remains accident detection, not authentication (no
  signing key exists; adding one is a key-management decision for the owner).

## Note on the stress results produced while these rounds ran

`results/stress_*.json` (untracked at the time of writing) were generated by the background job
while rounds 1 to 6 changed code, so the four experiments did not all run against one commit.
No change in these rounds alters a stress, planner or verifier number (each was an
output-neutral fix, covered by tests), so the numbers should be the same, but provenance is only
clean if the owner reruns `make stress` at the final commit and commits that output.
One row to read with care: the `scaling` row for n = 2000 has `verified_ok: false`. Re-running
the original commit (before any review change) gives the same result: the 2000-drone sphere at
3.2 m spacing extends below the altitude floor (768 altitude violations), so that plan is not a
verified plan and its stress figures describe an invalid input.
