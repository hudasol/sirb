# PX4 SITL replay (simulation only)

Generated by `scripts/make_sitl_doc.py` from `results/sitl_replay_*.json` (`scripts/sitl_replay.py`). Do not edit by hand. Predictions P31 to P33 and their grading are in `docs/PREDICTIONS.md`.

## What this is

A small offline experiment. A planned and exactly verified show of 2, 3 and 4 drones is streamed as offboard position and velocity setpoints to PX4 running as a simulated multirotor (simulation in hardware, SIH, vehicle `sihsim_quadx`, PX4 default parameters, no tuning). The simulated vehicles' positions are logged and compared with the plan. It runs only in the cloud workspace. It never connects to a real vehicle or radio, and the planner and verifier are not changed by it.

## Setup and measured limits of the workspace

The workspace has 2 cores and 8 GB of memory. Cloning PX4 with submodules (1.9 GB) took one to two minutes and `make px4_sitl_sih` about four minutes. Steps: clone `PX4/PX4-Autopilot` recursively and shallow, install the Python build dependencies (`empy` 3.3.4 needed its `em.py` copied into site packages because its wheel failed to build), run `make px4_sitl_sih`, start instances with `scripts/sitl_instances.sh start N`, then run `python scripts/sitl_replay.py N` (it needs the Python packages `pymavlink` and `psutil`, which are not dependencies of Sirb itself). Measured while replaying:

## Flown versus planned

Threshold 2.0 m. Planned separation is the exact verifier value for the plan; flown separation is computed on the logged paths resampled at 20 Hz. One run per vehicle count; PX4 runs in real time so runs are not repeatable to the last digit.

|---|---|---|---|---|---|

## How to read it

With default controller parameters the simulated vehicles do not follow the plan closely: the plan asks for speeds and accelerations that the default position controller does not deliver, so the tracking error reaches several metres and the flown minimum separation can fall far below the verified one, including below the threshold. This is what the verifier's wording already says: a pass applies to the planned polynomials, not to a flown path. It is not evidence about any real vehicle, since SIH uses a simple dynamics model with no wind, no GNSS error and no interaction between vehicles, and the comparison uses the wall clock to align the logs (an alignment error of 50 ms at 10 m/s is 0.5 m). A tuned controller, or planning to the controller's actual limits, would change these numbers; that was not done.
