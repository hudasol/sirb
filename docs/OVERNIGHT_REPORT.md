### B. Real GNSS parameters

Source found and cited: FAA GPS SPS Performance Analysis Report 131 (Q3 2025), Table 5-2 (US government work). From 26 sites, median 95% horizontal error 2.710 m gives a per axis sigma of 1.107 m (site range 0.670 to 3.240 m), written to `shows/gnss_faa_sps_standalone.json`. **Every value stays `assumed: true`**: the source gives the absolute error of one standalone receiver, while the model needs the relative error between drones, for which no public source was found. marsad and Tashwish publish nothing usable and were not used or modified.
**Sensitivity rerun with the sourced value not finished** when this report was generated (`results/sensitivity_faa.json` missing).
Prediction P15: pending.

### E. Reproducibility (Hungarian ties)

Done and verified on CI. Two causes, not one: last bit noise in the targets (CPU dependent trigonometry and matrix kernels) and tied assignments that flip when costs differ in the last bit. Fix: snap targets to a 2^-20 m grid, exact integer assignment costs, no BLAS or pow in leg construction (`docs/REPRODUCIBILITY.md`). The CI check against the committed copy is now hard. Every result derived from planned fleets changes (`docs/CHANGES.md`).
Fleet hashes now committed: `sirb_text_100` `dc4aba75`, `torus_300` `d17f2c1a`, `wall_500` `7283bef4`.
Prediction P13: Hit.

### H. Adversarial review

Done as a hostile read of the phase 6 changes (the review skill was not run, for lack of time). Findings and what was done:

1. Stale results next to changed code. Stream E changes every planned fleet, but the stress and sensitivity result files were not all regenerated (list in `docs/CHANGES.md`). Fixed in part (viewer data, planner benchmark); the rest is stated as stale in `docs/CHANGES.md` and below rather than hidden.
2. A sourced number that does not measure what the model needs. The FAA figure is absolute error; the model needs relative error. Kept `assumed: true` and said so in the file, in `docs/GNSS_SOURCED.md` and in every brief.
3. Encoding. `docs/GROUND_ROBOTS.md` was written in the Windows code page (a broken superscript). Fixed; other generators assume UTF-8 and must run with UTF-8 as default (Linux, or `PYTHONUTF8=1` on Windows).
4. Development result presented as a measurement. The grid planner's restart policy was tuned on the reported tasks; stated in `docs/GROUND_ROBOTS.md` and P14.
5. Organisation claims. The briefs were written to describe Sirb only; ADEO's remit was not verified and the brief says so. No partnership, endorsement or cost is claimed.
6. Attribution. Earlier phases' commits carry co author trailers and session links; phase 6 commits do not. History was not rewritten (hard rule), so the old trailers remain.
7. Test platform. Two tests fail on a Windows checkout only (`/dev/zero`, and CRLF conversion of the vendored three.js changing its hash); the Linux suite and CI are green.
