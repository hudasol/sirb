# Sourced GNSS parameters (stream B, phase 6)

Generated by `scripts/make_gnss_sourced_doc.py` from `results/gnss_faa_derivation.json`, `results/sensitivity.json`, `results/sensitivity_faa.json` and `results/margin.json`. Everything below the source table is **simulated**: a property of the model with the stated parameters, not of real aircraft.

## Source

* FAA GPS SPS Performance Analysis Report 131 (Q3 2025), Table 5-2: <https://www.nstb.tc.faa.gov/reports/FAA_SPS_PAN_Report_131_v1.0.pdf>, retrieved 2026-10-16.
* Licence: US government work, not subject to US copyright (17 U.S.C. 105). The extracted table is kept in `data/faa_sps_pan131_table5_2.csv` with the SHA-256 of the report.
* What it measures: the 95% horizontal and vertical position error of single frequency GPS (SPS) at fixed WAAS reference sites over each 24 hour period, against surveyed positions.

## What the source supports, and what it does not

* It supports the magnitude of the **absolute** error of one standalone receiver, that is a drone that has lost its RTK corrections and falls back to plain GPS.
* Sirb's model applies the bias **independently** to each degraded drone, so the separation it erodes is the **relative** error between two drones. Nearby receivers that track the same satellites share most of their error (orbit, clock, ionosphere, troposphere), so the relative error is expected to be smaller than the absolute one. No retrieved source gives it. Using the absolute figure for the relative one is a judgement, so **every value in `shows/gnss_faa_sps_standalone.json` stays `assumed: true`**, following the rule in `docs/GNSS_PARAMS.md`. No usable public source for the relative error was found.
* The degraded fraction (0.25), correlation time, white noise and dropout values have no source here; they are the scenario values and defaults.
* `hudasol/marsad` and the Tashwish project publish no position error statistics that this format can use (`docs/GNSS_PARAMS.md`); nothing from them is used.

## Derivation

Per axis sigma of a circular Gaussian whose 95% horizontal radius is R95: sigma = R95 / 2.4477. Vertical (one dimension): sigma_z = V95 / 1.9600.

## Relative error between drones (phase 6 study)

* Source read: Carvalho et al. (2023), Sensors 23(21):8835, Table 1, <https://doi.org/10.3390/s23218835>, licence CC BY 4.0 (stated on the article page), retrieved 2026-10-18. The table used is kept in `data/carvalho2023_sensors_table1.csv`.
* In one 800 s run a low cost receiver on a moving rover had a mean horizontal error of 1.202 m standalone and 0.713 m after pseudorange differencing against a reference station 1.184 km away, which cancels the errors common to both sites (ratio 0.59).
* Mapped to a per axis sigma for a circular Gaussian (mean radius / 1.2533): 0.569 m, written to `shows/gnss_relative_literature.json`.
* This is a **literature value, not a measurement of the target hardware**: one receiver type, one run, a high grade reference instead of a second low cost receiver, tree canopy, a Kalman filter, GPS L1 only. The mapping and the setting are judgements, so the flag stays `assumed: true`. No source was found that measures the error between two nearby low cost receivers without corrections, which is the quantity the model uses.
* Consequence: **the stressed verdict hinges on this single unsourced parameter**. Over the values discussed here (the literature anchored value above, the FAA absolute range, and the assumed sweep in `docs/SENSITIVITY.md`) the required separation changes by metres (`docs/MARGIN.md`).

## Limits

The model's GNSS errors are independent between drones; real standalone errors are largely common to nearby drones, so these sourced runs are expected to overstate relative error. A fleet wide common error (for example jamming or spoofing) is not modelled at all (`docs/HAZARDS.md`). The reference sites are in the United States, Canada and Mexico, not in the UAE.
